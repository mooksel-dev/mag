Finance Hub — deployment & flows

Left to right: the device, the Web Backend AWS accounts, the Identity AWS accounts (where FTM runs), and outside systems. green new · amber changed · grey unchanged. Arrows: 1–6 tab read path, A–F ingest path, G alerts, dashed = route not decided.

#FlowProtocol / auth
1–2The mobile app sends financeHubOverview, …Spending, …Income, …Bills and …CardShield to the GraphQL gateway.GraphQL over HTTPS · Bearer user JWT
3The graphql-layer Lambda calls the FTM REST API through IDENTITY_API_ORIGIN. This crosses from the Web Backend accounts into the Identity accounts over the public domain.REST GET /ftm/hub/* · the same Bearer is forwarded
4The Identity API Gateway checks the token, then calls the hub API Lambda.CUSTOM authorizer · AWS_PROXY
5The hub API reads ftm.transactions and ftm_hub.* in DocumentDB, and the item view in DynamoDB for connection state. Month totals are computed on read.Mongo driver inside the VPC · DynamoDB SDK
6The hub reads breach records for Card Shield.source TBD
APlaid sends webhooks through the gateway to ingest. Ingest pulls with /transactions/sync.HTTPS · the webhook has no auth or signature (idea filed)
B–DIngest appends to the DynamoDB event stores. The table stream goes to the SNS identity topic, and filter policies fan it out to the SQS queues.AWS internal, same account
EThe query populator upserts ftm.transactions. It now also handles FtmTransactionModified.SQS → Lambda → DocumentDB
FThe hub worker (NEW) gets transaction and item events. It recomputes the user's streams, card-on-file and alerts into ftm_hub.*.SQS → Lambda → DocumentDB
GThe hub worker publishes FtmHubAlertCreated to SNS. AP turns it into an event webhook, which lands in al-sneed's feed_ingest SQS for push and feed.SNS → AP → cross-account SQS (AP roles). The SNS → AP bridge is a guess.
HAsk Aura calls the budget tools proposeBudget and calculateBudget.Route TBD: through the gateway or straight to /ftm/hub
